基础生理

专项检测

💜 ecg 🩸 bloodGlucose ⚖️ bodyComposition 😊 emotion ☀️ uv

4. 三层数据模型

┌─────────────────────────────────────────┐ │ 展示层：FusedMetric │ ← 首页/健康页看到的 │ profileId + 每个指标一个"最佳值" │ ├─────────────────────────────────────────┤ │ 融合层：FusionPolicy │ ← 选哪个来源的值 │ 按精度/新鲜度/用户偏好 排序 │ ├─────────────────────────────────────────┤ │ 原始层：RawReading │ ← 所有设备原始数据全保留 │ profileId + source + timestamp + accuracy │ └─────────────────────────────────────────┘

4.1 原始层 — RawReading

每次测量的原始结果，全部保留，不丢弃。

字段类型说明
idUUID唯一标识
profileIdString归属哪个家庭成员
metricTypeHealthMetricType什么指标
sourceDeviceType哪个设备 (.ring / .phone / .watch)
sourceNameString"Vvewell Ring" / "iPhone Camera"
timestampDate测量时间
valueDouble主值（72, 98, 36.5...）
unitString"bpm", "%", "°C"
accuracyReadingAccuracy精度等级
metadata[String: Any]?附加数据（ECG 波形等）

精度等级

📱
estimated = 1
算法估算（rPPG）
💍
consumer = 2
消费级传感器
🏥
medical = 3
医疗级认证设备

4.2 融合层 — FusionPolicy

策略逻辑适用场景
highestAccuracy取精度最高的来源；同精度取最近的默认 大多数指标
mostRecent取时间戳最新的读数实时性优先场景
average多来源数值平均参考性指标
userPreferred用户指定的设备优先用户手动覆盖

默认策略分配

指标默认策略原因
heartRate / spo2 / stresshighestAccuracyRing 传感器比 rPPG 准
ecg / bloodGlucosehighestAccuracy通常只有一个来源
sleephighestAccuracyRing 持续佩戴监测最准
steps / distancehighestAccuracy手表/手环计步更准

用户可在设置中覆盖：「心率数据来源：自动（推荐）/ Ring / iPhone / Watch」

4.3 展示层 — FusedMetric

UI 层消费的最终数据。每个成员、每个指标一个融合后的值，附带所有原始来源可展开查看。

5. 融合引擎

MetricFusionEngine.fuse(readings:for:) 输入: [RawReading] (同一成员，同一指标，不同来源) │ ├─ 只有 1 个来源 → 直接返回 │ ├─ 用户指定了 preferredSource? │ ├─ 有该来源的读数 → 用它 │ └─ 没有 → fallback 到 highestAccuracy │ ├─ strategy == .highestAccuracy │ → 按 accuracy 降序，取最高；同精度取最近的 │ ├─ strategy == .mostRecent │ → 按 timestamp 降序，取最新的 │ └─ strategy == .average → 计算数值平均，source 标记为 "mixed"

8. UI 展示规则

首页 / 健康页

  • 显示当前成员的 FusedMetric
  • 多来源时显示 "2 sources" 提示
  • 顶部头像横滑切换成员
  • 点击指标进入详情

指标详情页

  • 默认显示融合后的趋势线
  • 筛选器：全部 / Ring / iPhone / Watch
  • 多来源叠加显示（不同颜色）
  • 每个数据点标注来源图标

健康检查页

  • 测量前显示"为谁测量"选择器
  • 结果标注来源设备 + 归属成员
  • 同一指标有近期数据可显示对比
